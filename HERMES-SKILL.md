# Blip: Local Vision for Hermes

A standalone llama-server process running a VLM (Qwen2.5-VL-7B recommended) on CUDA
as a local vision fallback. Hermes routes `vision_analyze` and `browser_vision`
through it automatically when `auxiliary.vision` is configured.

## Architecture

```
Hermes Agent → call_llm(task="vision")
    → resolve_vision_provider_client()
    → config.yaml: auxiliary.vision
    → OpenAI-compatible HTTP client → http://127.0.0.1:BLIP_PORT/v1
    → blip-auth-proxy.py (Bearer token check, port BLIP_PORT)
    → llama-server.exe (internal, port BLIP_PORT+1)
    → VLM GGUF model (Qwen2.5-VL-7B / SmolVLM / Gemma-3)
```

## Quick Commands

```bash
# Start the server (with Qwen2.5-VL-7B)
BLIP_PORT=12100 BLIP_LLAMA_BIN=/path/to/llama-server.exe \
  BLIP_MODEL_DIR=~/.hermes/models/qwen-vl \
  BLIP_MODEL_FILE=Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf \
  BLIP_MMPROJ_FILE=mmproj-Qwen2.5-VL-7B-Instruct-Q8_0.gguf \
  bash ~/.hermes/scripts/blip.sh start

# Stop it
bash ~/.hermes/scripts/blip.sh stop

# Check status
bash ~/.hermes/scripts/blip.sh status

# Show API key
bash ~/.hermes/scripts/blip.sh show-key

# Full setup (build + download + start)
BLIP_HF_REPO=ggml-org/Qwen2.5-VL-7B-Instruct-GGUF bash ~/.hermes/scripts/blip.sh setup

# Test the API
curl -s -H "Authorization: Bearer $(bash ~/.hermes/scripts/blip.sh show-key)" \
  http://127.0.0.1:12100/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf","messages":[{"role":"user","content":"hi"}],"max_tokens":10}'
```

## Required Config

    provider: openai

## Getting llama-server

**Recommended - build from source (any OS, no pip):**
```bash
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j --target llama-server
```

Package managers: `brew install llama.cpp` (macOS), `winget install llama.cpp` (Windows).
Pre-built binaries: https://github.com/ggml-org/llama.cpp/releases

Avoid `pip install llama-cpp-python` - requires same build toolchain but with less CUDA/Metal control.

## Env Vars (ALL configurable - nothing hardcoded)

| Var | Default | Purpose |
|-----|---------|---------|
| `BLIP_PORT` | 11788 | Base port (auto-falls forward) |
| `BLIP_HOST` | 127.0.0.1 | Bind address |
| `BLIP_MODEL_DIR` | ~/.hermes/models/blip | Model directory |
| `BLIP_MODEL_FILE` | SmolVLM-Instruct-Q4_K_M.gguf | Model GGUF filename |
| `BLIP_MMPROJ_FILE` | mmproj-SmolVLM-Instruct-Q8_0.gguf | MMProj GGUF filename |
| `BLIP_LLAMA_BIN` | (auto-detect) | Path to llama-server binary |
| `BLIP_SCRIPTS_DIR` | ~/.hermes/scripts | Scripts directory |
| `BLIP_PID_FILE` | $BLIP_SCRIPTS_DIR/blip-server.pid | PID file path |
| `BLIP_AUTH_KEY_FILE` | $BLIP_SCRIPTS_DIR/blip-auth.key | Auth key file path |
| `BLIP_ACTIVITY_FILE` | $BLIP_SCRIPTS_DIR/blip-last-used | Watchdog activity timestamp |
| `BLIP_IDLE_TIMEOUT` | 90 | Minutes before idle shutdown (0=indefinite) |
| `BLIP_CONTEXT_SIZE` | 8192 | Context window (tokens) |
| `BLIP_IMAGE_MIN_TOKENS` | -1 | Min image tokens (-1 = auto) |
| `BLIP_IMAGE_MAX_TOKENS` | -1 | Max image tokens (-1 = auto) |
| `BLIP_NGL` | -1 | GPU layers (-1 = all) |
| `BLIP_THREADS` | -1 | CPU threads (-1 = auto) |
| `BLIP_FLASH_ATTN` | on | Flash attention (on/off) |
| `BLIP_HF_REPO` | ggml-org/SmolVLM-Instruct-GGUF | HF repo for model download |
| `BLIP_HERMES_CONFIG` | ~/.hermes/config.yaml | Hermes config path |

## Switching Models

```bash
# SmolVLM (2B, fast, 1.1 GB VRAM - crude results)
BLIP_HF_REPO=ggml-org/SmolVLM-Instruct-GGUF blip.sh setup

# Qwen2.5-VL-7B (7B, excellent quality, 5 GB VRAM - recommended)
BLIP_HF_REPO=ggml-org/Qwen2.5-VL-7B-Instruct-GGUF blip.sh setup

# Gemma 3 4B (4B, good balance)
BLIP_HF_REPO=ggml-org/gemma-3-4b-it-GGUF blip.sh setup
```

## Model Download Paths

Models live at `$BLIP_MODEL_DIR` (default: `~/.hermes/models/blip/`).
The `setup` command downloads from HuggingFace. Already-downloaded models
in other directories (e.g. `~/.hermes/models/qwen-vl/`) can be reused by
setting `BLIP_MODEL_DIR` to the existing path.

## $HOME Override for Hermes Profiles

Hermes profiles override `$HOME` to the profile directory, which breaks
path resolution in scripts. To work around this, pass `HOME=/real/home`
before `blip.sh`, or set all `BLIP_*_FILE`/`BLIP_*_DIR` env vars to
absolute paths.

## Sequential Multi-Image Analysis

The server handles sequential image analysis without issues:
- Each request is stateless - KV cache freed between calls
- Prompt caching works: ~99% of prompt tokens cached on repeat runs
- A 3MB PNG uses ~2061 image tokens with Qwen2.5-VL-7B
- With 8192 context, ~3-4 detailed images per request max
- No VRAM leak across sequential runs (tested with 3 consecutive analyses)

## Lifecycle

- **Watchdog cron:** runs every 10 min (no_agent=true via script)
  - Server down → start it
  - Server unresponsive → kill + restart
  - Server idle >$BLIP_IDLE_TIMEOUT min → shutdown (frees ~5 GB VRAM)

## User Commands

When the user types `/blip <subcommand>` or asks about Blip, run the
appropriate `blip.sh` command:

| User says... | Run... |
|-------------|--------|
| `/blip start` or "start blip" | `HOME=/home bash ~/.hermes/scripts/blip.sh start` |
| `/blip stop` or "stop blip" | `bash ~/.hermes/scripts/blip.sh stop` |
| `/blip status` or "blip status" | `bash ~/.hermes/scripts/blip.sh status` |
| `/blip key` or "show key" | `bash ~/.hermes/scripts/blip.sh show-key` |
| `/blip setup` or "install blip" | `HOME=/home bash ~/.hermes/scripts/blip.sh setup` |
| `/blip restart` | `bash ~/.hermes/scripts/blip.sh restart` |

## Design Principles

1. **Zero hardcoded values** - every path, port, filename, and flag comes from an env var with a sensible default
2. **Seamless setup** - `blip.sh setup` builds llama.cpp, downloads model, configures auth, and starts the server
3. **Private by design** - auth proxy prevents CSRF compute hijacking; all traffic stays on localhost
4. **Shareable** - all env vars documented; works on any machine with any Hermes profile
